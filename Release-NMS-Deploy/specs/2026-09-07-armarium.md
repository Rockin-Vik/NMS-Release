# Armarium — inventory clicky that opens vault storage

Status: implemented on this tree (2026-09-07). Gated by `Custom:DimensionalVault` (compiled default on; custom **v45** sets live `rule_values`).
Date: 2026-09-07
Governs: one lore / no-drop inventory item named **Armarium** that is auto-summoned if missing and whose right-click opens vault storage (pages 1–6, Bank, Merchant, Proc Locker, clicky pages).
Companion: `2026-09-06-nmsloot-server-design.md` (F3–F6). This spec does not replace the vault ImGui buttons.

Player-facing name is **Armarium**. Do not call the item Dimensional Armory or Dimensional Vault. The rule name `Custom:DimensionalVault`, `#vault_*` commands, and `VAULTDATA|` chat stay — those are the installed add-on wire, not the item name.

## 0. Decisions

| # | Decision | Why |
| --- | --- | --- |
| D1 | **One item**, named Armarium. Right-click opens the vault window (page 1). Bank / Merchant / Proc Locker / clickies stay on that window. | Owner: show up in bags and be clickable; not a typed `#` command. Name is Armarium, not Dimensional Vault. |
| D2 | **Auto-summon on zone-in / login if missing.** Inventory, bags, the entire cursor queue (not just the visible head), bank, shared bank, vault, and the character's corpses all count as “have it.” | Owner choice (grant path 2). Destroy / vendor-loss comes back on the next zone-in. One persistent key: a corpse copy must not cause a second grant. |
| D3 | **Item id `9011013`.** Cloned from NMS Satchel of the Hero `9011010` like the GM Starter Box (`9011012`), then converted to a non-container key. | Same clone pattern as custom v31. Not a bag: right-click must fire the click, not open a container. |
| D4 | **Lore + no-drop + no-transfer.** Persist across camp (`norent = 1`, rentable). `NoRent == 0` is deleted after a long camp. Bound even under Firiona Vie (`fvnodrop = 1` and identity in `IsDroppable`). | One per character in inventory/bank. Cannot trade or sell. Gear uses the FV + attune loop; this key does not. |
| D5 | **Refuse vault deposit** (cursor deposit, a bag that contains the key, bag-in-vault, and `/nmsloot` Vault). Refusal is recursive. | Vault storage is invisible to `CountItem`. Deposit-then-regrant would duplicate the key. |
| D6 | **Server intercepts the click.** Dummy `clickeffect` is spell id `1` so the RoF2 client shows a clicky. The zone never casts that spell. Spell `1` is not a shipped spell (`IsValidSpell` rejects ids below 2). | Opening storage is `NmsVaultHandlePage(c, 1)` → `VAULTDATA\|`. Same wire as `#vault_page 1`. |
| D7 | **Fail closed with the vault rule.** Rule off, tables missing, item absent from items/shared memory, or a vault/corpse ownership read that does not confirm absence: do not grant. Click says the Armarium is sealed when the rule or tables are down. | Matches F3–F6. Query failure is not “not owned.” |
| D8 | **Do not port vault ImGui into `Release-NMS-Client`.** The installed add-on still draws the window from `VAULTDATA\|`. Enabling the rule treats that add-on as the operational prerequisite. | Same as loot spec D1. Raw `VAULTDATA\|` chat without the add-on is accepted. |
| D9 | **Identity is not remainder-only.** `9011013 % 1000000 == 11013`, and `11013` is stock Boots of Quickness. Match `id >= 9011013` **and** `id % 1000000 == 11013`. | Keeps D3 and upgrade-tier copies. Boots of Quickness must not count as owned, block vault deposit, or open the Armarium. |

## 1. Player-facing behaviour

When `Custom:DimensionalVault` is on and `character_nms_vault` is ready:

1. On zone-in / login, if the character does not have an Armarium identity match in possessions, bags, the full cursor queue, bank, shared bank, vault, or a corpse, summon it into a free inventory/bag slot that fits size 1 / key type, or the cursor if those are full.
2. Right-click Armarium → vault UI opens on page 1. From there: pages 1–6 storage, 7–8 clickies, 9 Proc Locker, Bank, Merchant.
3. Rule off: no grant. A leftover item still consumes the click and tells the player the Armarium is sealed.

`TRIUNE > Loot` is unchanged. It is not the Armarium.

| `maxcharges` | `-1` (unlimited) |
| `nodrop` | `0` (NO DROP in this schema) |
| `norent` | `1` (rentable; `0` is deleted after a long camp) |
| `loregroup` | `-1` |
| `notransfer` | `1` |
| `fvnodrop` | `1` (stays no-drop on a Firiona Vie client) |
| `slots` | `0` (inventory click, not worn) |

Runtime identity: `item_id >= 9011013 && (item_id % 1000000) == 11013`. Do not use remainder equality alone.

## 3. Deploy

- Content migration (custom **v43**, `content_schema_update = true`). `origin/main` already used v41 for vault instance-state columns and v42 for learned-spell tables. Check is the full item contract (id, name, class/type, bagslots, bagtype, book, slots, nodrop, norent, notransfer, fvnodrop, attuneable, loregroup, `clicktype`, `clickeffect`, `clickname='Open Armarium'`, `casttime=0`, `maxcharges=-1`). If both `9011010` and `9011013` are missing, the SQL errors (NULL into a NOT NULL sentinel) and `custom_version` is not stamped. If a previous apply left a wrong `norent`, `attuneable`, `clickname`, `casttime`, or charges row, the check stays empty and the `UPDATE` repairs it. The health check selects those same click/charge fields.
- Player migration (custom **v44**) sets `World:FVNoDropFlag = 1`. That is the gear loop, not this item. Re-run `shared_memory` after it lands.
- Player migration (custom **v45**) sets `Custom:DimensionalVault = true` so Armarium grant and vault commands are on. A leftover `false`/`0` row is rewritten; an existing `true` is not stomped. `#reloadrules` or a zone bounce picks it up.
- If a local database already stamped an older Armarium draft as v41: the item row may already exist. v43’s full-contract check skips the SQL when the payload is already correct; if `norent` or click fields are wrong, the check stays empty and the `UPDATE` repairs it. Do not assume a stamp means the payload is correct.
- Re-run `shared_memory` after the item lands. Zone `GetItem(9011013)` is the grant gate; a stale shared-memory snapshot skips the summon with no chat spam.
- Split player/content schemas: v43 targets content; v44 and v45 target player `rule_values`. `nms_content_health_check.sql` must be run against the content schema for `items` and against the player schema for `db_version` / `rule_values` / `character_nms_*`.

## 4. Verification

- Rule off: no item granted; leftover click is sealed; `#vault_*` still fail closed as today.
- Rule on, item in items + shared memory, empty inventory slot: item appears, named Armarium.
- Right-click: vault window opens (installed add-on). No heal / dummy spell lands.
- Destroy the item, zone: it is granted again.
- Bank the item, zone: it is not granted again.
- Boots of Quickness (`11013`) in inventory: Armarium is still granted; the boots can be vaulted; clicking the boots does not open the Armarium.
- Cursor-deposit into vault: refused; item stays on the cursor.
- `/nmsloot` Vault on this item: refused, not “vault is full.”
- No free bag/inventory slot that fits size 1 / key: the item is summoned to the cursor if the cursor has fewer than `CURSOR_BAG_COUNT` (200 on RoF2) persisted entries. A full cursor is fail-closed: no grant and no yellow bind message. `SaveCursor` can return true after dropping a 201st entry.
- Buried cursor copy (another item is the visible head): zone does not grant a second key.
- Vault or corpse ownership query failure: no grant and no yellow binding message.
- Under `World:FVNoDropFlag = 1`: Armarium cannot be traded, dropped, or shared-banked. Wearable no-drop gear can, until equipped.
- Long camp (>30 minutes) with the rule on: existing key is still there; no rebind message.
- Item-loss corpse: zone does not grant a second key while that corpse still holds it.
- Repo `dinput8.dll` without vault chrome: server still sends `VAULTDATA\|`; player may see those chat lines. Same as `#vault_page`. Enabling the rule assumes the installed add-on.
